# Across the Room: product audit for the implementation prompt

Prepared 5 October 2026 (Asia/Kolkata). This is a local specification audit, not an implementation or test report. No device, acoustic, clinical, latency, security or deployment test was executed for this audit. The latest detailed specification is `research/_working/spec_FTV-4.md`, especially its 4 October §13 amendments; broad proposals in `LAST30DAYS_IDEAS_AND_FEATURES.md` do not override that section.

## Product and current scope

- Fire TV primary track: React Native for Vega, genuinely built and running on the Vega Virtual Device (VVD). The phone is an Android Chrome browser microphone on a fixed mark beside the TV, 2.5–3 m from the speaker. The TV never captures audio. No model performs scoring. (`spec_FTV-4.md:3–19`, `RECOMMENDATION.md:12`)
- Adult speaker follows practice already recommended by their clinician; household listener can participate. Scope is practice support, without diagnosis, treatment, outcome or intelligibility claims. Required disclaimer: “Not a medical device. Does not diagnose or treat any condition.” (`spec_FTV-4.md:13`, `:30–35`)
- Flow: pair by room code/QR → explicit phone microphone permission/start → 5-second quiet floor → 6-second calibration phrase → 30-second sustained ahh → 1–10 household phrases with 6-second measurement windows → user-paced summary and 7-calendar-day history. All speaker actions use OK, Back and D-pad after the per-session phone start. (`spec_FTV-4.md:31–66`, `:72–99`)
- Phone processes audio locally, sends numeric measurements and control/data events over AWS WebSocket relay in Mumbai. TV owns deterministic verdicts and local AsyncStorage history. Relay uses API Gateway, Lambda, DynamoDB pairing records; phone page uses S3/CloudFront. HTTPS polling is a capability fallback; local relay and explicitly labelled fixture replay are judge routes. (`spec_FTV-4.md:202–292`)
- Open Source contribution: reusable ten-foot-meter and phone-mic-meter modules, MIT, documented/tested; a separate phone-pairing library is rejected. AWS Builder relies on substantive runtime relay integration, with development tooling eligibility to be verified from current official rules. (`spec_FTV-4.md:602–624`, `:865`)
- Local situation assumes solo build, India; actual team size and available Android hardware remain unknown. Previous ~102.5-hour estimates are estimates of human work, not proven agent execution timings. (`IDEATION_CONTEXT.md:5–10`, `spec_FTV-4.md:877`)

## Acceptance criteria that belong in the build prompt

1. A native VVD package actually installs/launches; the complete journey runs using Select/Back/D-pad; remote script and genuine footage provide evidence. Every focusable has visible focus, accessible label/role, coherent focus return; UI scale is observed, not just imported. TV prompts are legible at 3 m with text as well as color. (`spec_FTV-4.md:21–35`, `:119–147`)
2. Speaker does not touch the phone after per-session mic start. Listener taps do not move the phone; family mode can be off. On next session, permission/start behavior is honestly documented. (`spec_FTV-4.md:35`, `:804`, `:816`)
3. TV audio is silent during every measurement window. Arc 20 Hz is target; 10 Hz interpolation is an observed capability fallback. WSS phone-to-visible-TV p50 target <300 ms; polling target <500 ms. If neither passes, show end-of-window result and measured limitation. Do not fabricate a responsive live meter. Camera clap test, not clock estimate, supplies latency ground truth. (`spec_FTV-4.md:42–48`, `:539–542`)
4. Same-session rule uses relative dBFS above noise, not calibrated dB SPL. Noise gate refuses unsafe/uninterpretable results; silence, dropped link, stale/incomplete windows score nothing. Store summaries, not raw audio or normal-operation number streams. (`spec_FTV-4.md:380–390`, `:431–459`, `:567`)
5. Phrase input 1–10 items, 1–60 chars each, plain text. Cue 1–12 chars. No markup execution, prompt-text instructions, out-of-role message, unknown version/type or malformed number may alter score or destructive state. (`spec_FTV-4.md:372–378`, `:563–567`)
6. Persist sessions idempotently by session/window identity, survive crash/relaunch with explicit resume/discard, derive 7-day data by real calendar date. Deletion/reset require explicit TV confirmation; delete all atr-prefixed storage keys; no phone reset/delete path. (`spec_FTV-4.md:465–526`)
7. Family cue cap, rating/reveal/skip ordering, late taps, first-attempt counting and disagreement are deterministic and tested. Blind-check render must contain no hidden-but-mounted arc/band. (`spec_FTV-4.md:797`, `:821`)
8. Mic-state badge is acknowledged state, not an optimistic icon. Test sample emission boundaries and track.stop/release on summary, cancellation, disconnect timeout, page teardown and fatal error. Local spec expressly covers summary; safe lifecycle handling must cover all exits. (`spec_FTV-4.md:804–809`)
9. Verified cloud relay has pairing conflict, bad-token, expiry, replay, payload limits, redaction, GoneException and reconnect tests. Real CloudWatch inspection confirms no bodies/tokens/phrases. Lifetime is read-enforced; DynamoDB TTL cleanup is asynchronous. (`spec_FTV-4.md:374–378`, `:454–471`)
10. Results are evidence records with build/device/browser/date/metric/value/pass-fail/notes. Report unavailable manual tests as pending/blocking, never passed. Physical acoustic behavior, usability and VoiceView require real device/human observation. (`spec_FTV-4.md:529–567`)

## Contradictions and recommended ADR resolutions

| Conflict or gap | Where | Resolution for production prompt |
|---|---|---|
| Pre-window gate needs last 2 s of samples, but new privacy design transmits samples only in windows. | `spec_FTV-4.md:91`, `:809` | Keep a bounded ephemeral local analysis ring while mic is open. Add an explicit 2-second precheck/control window and transmit only its aggregate floor/quality result, labelled Measuring. Ordinary sample frames transmit only during declared calibration/ahh/phrase windows. Preserve no persisted audio and no background outbound samples. |
| “Only levels and phrases” omits listener verdict/cue and technical control metadata. “Only numbers” is also false. | `spec_FTV-4.md:186`, `:241`, `:326–378` | Use: “Audio is processed on this phone and never saved or uploaded. Only levels, typed phrases, listener responses, and connection details are sent to the relay and TV.” State transient polling buffer retention separately if used. Do not claim end-to-end encryption when relay sees cleartext payload. |
| Relay supposedly never inspects payload, yet must validate schemas/types/size. | `spec_FTV-4.md:372–378`, `:457` | Relay validates minimal schemas/roles/limits and forwards; it never logs message bodies or interprets phrase meaning. Schema validators must be shared with clients/local relay. |
| Polling fallback stores RING measurement payload in DynamoDB, but privacy says room/connection records only and relay never stores payload. | `spec_FTV-4.md:66`, `:408`, `:457` | Document actual ephemeral aggregate/sample/control retention for polling; bounded size, immediate read cleanup/expiry checks and explicit application deletion. TTL 2 h is not a guarantee of two-second physical deletion. Prefer minimizing polling buffer content. |
| Window envelopes usually lack session_id, yet TV is told to reject mismatched sessions. Window id examples vary phrase-03 vs w_p03. | `spec_FTV-4.md:328–358`, `:376`, `:433`, `:503` | Canonical contract includes protocol version, session_id, unique window_id, sequence and request/event identity on every session-bound event. Validate direction and current state. Enforce stale, duplicate, replay and out-of-order behavior explicitly. |
| Room-only HMAC token, reconnect matching same token hash, and action/to trusted fields leave roles and hijack boundaries underspecified. Room creation contract missing. | `spec_FTV-4.md:366–378`, `:454–458` | Specify server-issued random room identity, high-entropy per-role credentials bound to room/role/client/expiry/nonce; one slot per role; atomic create/join/reconnect; rate-limit code guesses and room creation; Origin validation and token revocation. Derive sender role/room from authenticated connection, not supplied from/to fields. |
| 6 dB accepted calibration cannot clear 10 dB noisy gate in a unchanged quiet room. | `spec_FTV-4.md:386`, `:389` | Resolve in ADR and fixtures: require valid calibration to meet the same speech/noise separation floor used in later prechecks, or revise gate with evidence. Never accept a band that inherently blocks all following windows. |
| VAD starts after 100 ms, but cough under 200 ms is expected not to onset. | `spec_FTV-4.md:385`, `:549–550` | Define candidate onset separately from qualified phonation; minimum duration ≥200 ms for counting with onset backdating, or change declared expectation. Test 100/150/200 ms transients explicitly. |
| VAD duration described as impossible for AGC to corrupt. | `spec_FTV-4.md:53`, `RECOMMENDATION.md:167` | Correct: duration is less dependent on amplitude calibration, but threshold-based activity can still be altered by AGC/noise/voice quality. Validate timing independently on unsupported/AGC-on devices. Without validated activity signal offer clearly labelled manual/listener timing or mark unavailable. |
| One tone monotonicity pass enables adaptive cross-session dB escalation. | `spec_FTV-4.md:388`, `:534–536` | Default cross-session amplitude/adaptive goals off. Monotonicity alone is not clinical calibration and does not establish across-day/device/place comparability. Preserve time/history metrics; any later amplitude comparison requires same device/input/browser/settings/geometry and repeatability evidence. No automatic +1 dB encouragement or +6 escalation in initial production scope. |
| Calibration p95 over VAD-active frames, phrase p95 scope not equally specified. | `spec_FTV-4.md:335`, `:386–387` | Explicitly specify active-frame percentile, minimum active duration/coverage, percentile algorithm and invalid-window rules. Tests must exercise short utterances, silence and continuous noise, not only threshold-adjacent numbers. |
| RMS is called reached despite being unable to judge words/voice identity. | `spec_FTV-4.md:93–95`, `:817` | Explain verdict as above today's relative band at the listener microphone; distinguish listener Heard/Not heard as subjective audibility, never intelligibility or clinical correctness. Noise, music, cough and another speaker are falsification cases. |
| Global aria-live announcements can violate silent windows and contaminate microphone. | `spec_FTV-4.md:114`, `:126–128` | Coordinate VoiceView announcements before windows; defer routine live updates during capture, provide visual states, retain emergency stop accessibility. Verify actual screen-reader audio timing rather than assuming. |
| Recommendation K4 still lists family mode first cut; detailed amendments protect it. | `RECOMMENDATION.md:135`, `spec_FTV-4.md:756`, `:877` | Apply latest §13: drop unstarted stretch, then OSS publication (keep reusable code), family/listener mode last. Keep privacy/mic shutdown as essential production behavior even though fallback §13.8 calls badge capacity-dependent. |
| “No touch after pairing”/≤4 presses vs mandatory new mic start after end_session. | `spec_FTV-4.md:32–35`, `:804` | Acceptance applies after per-session Start mic/permission and completed pairing. Include setup steps honestly in README and demo; count exact remote presses on real implementation. |
| Older text names Repeat, Polly and export as core and calls fallback blinded. | `spec_FTV-4.md:93`, `:151`, `RECOMMENDATION.md:167`, `LAST30DAYS_IDEAS_AND_FEATURES.md:457` | §13 controls: cue replaces Repeat, text core, export stretch; fallback is independent two-sided, not fully blind in one room. |
| Five repeats vs ten repeats in AGC protocol; speaker steps calibrated using the same phone. | `RECOMMENDATION.md:124`, `spec_FTV-4.md:534` | Use 10 randomized repeats at 3 input levels per tested device/session. Independent reference/source calibration is preferred; otherwise say nominal playback settings, not known 6 dB acoustic differences. Tone test is engineering qualification, not speech validity proof. |
| Fixture sample chart wording can encourage sample history whenever fewer than 7 sessions exist. | `spec_FTV-4.md:54`, `:721` | Production displays actual days and missing/no-session states; never fill real history with invented data. Sample charts exist only in explicit fixture/demo mode with persistent label. |

## Listener Edition and gates

FTV-4F is an in-product fallback only if far-field amplitude reliability fails while Vega and transport work. It uses listener Heard/Not heard as the headline metric, relative arc explicitly per-session, and validated activity duration. Speaker Felt loud/Felt normal and listener response are independently submitted, revealed only after both or explicit skip. Same cue code is shared; no absolute or adaptive cross-session loudness target. (`spec_FTV-4.md:867–873`)

The prior plan has dated gates: VVD hello world by 7 October 20:00 IST; architecture/AGC gate 8 October 20:00; unedited core take 14 October 20:00; feature freeze 19 October 12:00. It also proposes switching to entirely different products when early gates fail. The new user asks specifically for Across the Room: preserve that requested objective and report a hard platform blocker or propose an alternative without silently building Mail Check/OutPass. These dates are internal planning dates; official hackathon deadlines must be checked live by the lead researcher. (`RECOMMENDATION.md:128–165`)

## Evidence needed before calling it production ready

- Physical Android Chrome microphone qualification and actual VVD full-session run, permission-denied/pending behavior, screen off/background/revoked permission, microphone/AudioContext suspend-resume, 15-minute wake/thermal/battery session, phone moved mid-session and reconnect.
- Acoustic reference validity and speech/noise/cough/second-speaker falsification; independent labels and confidence limits. Synthetic threshold tests alone cannot prove microphone accuracy or real audibility.
- Real relay auth/isolation, paired-role forgery, brute-force controls, reconnection races, stale sessions, payload redaction, bounded retention, rate/load/soak behavior and teardown.
- Complete D-pad and accessible focus journey, UI scale and VoiceView behavior observed on VVD; persistent local data migration/corruption/recovery and deletion verified.
- Reproducible clean clone install/build, pinned compatible dependencies, lockfiles, CI gates, native artifact provenance/checksum, IaC plan, rollback/incident runbook, budget alarms and hosted keep-alive checks.
- Honest outcome: “implementation complete, validation pending” if any physical/platform/user/account evidence remains unavailable. No agent can mark these external tests passed by writing tests, a report or a simulated demo.
