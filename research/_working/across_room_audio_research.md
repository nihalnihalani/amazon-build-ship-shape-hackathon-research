## Measurement honesty and production defaults

These are engineering conclusions from the signal type and local spec, not medical efficacy findings:

- RMS dBFS relative to a measured room floor can indicate how much digital amplitude reached this microphone. It cannot establish absolute dB SPL, word recognition, voice identity, clinical outcome or a hearing threshold. A loud cough, music or second speaker can fool level-only scoring.
- Browser settings false is reported configuration; hardware/OS compression, input selection and changing acoustics still need falsification tests. Do not equate constraint support with reliable acoustics.
- A tone monotonicity pass is necessary qualification for the chosen device/input, not sufficient proof of speech/audibility validity or cross-day comparability. Keep adaptive cross-session +1 dB/+6 dB targets disabled by default. Recalibration is within-session engineering setup, not prescribed treatment.
- VAD measures time after a threshold decision, so AGC/noise can alter detected onset/offset and duration. Replace the local spec's “AGC cannot corrupt it” claim with a qualified statement, and independently test duration on AGC-on/unknown devices before enabling it in the fallback.
- A 20 Hz UI/network update schedule is not a guaranteed 20 Hz audio clock. Use capture timestamps for duration, actual elapsed time/frame coverage, explicit dropped/suspended-frame validity rules, and sample-time weighting if cadence varies. Do not fabricate sample timings from expected interval counts.
- At 48 kHz, 2048 samples cover about 42.7 ms; 50 ms polling leaves temporal gaps. At 44.1 kHz coverage is about 46.4 ms. VAD timing accuracy must be established against independent labels; use an AudioWorklet-based continuous analysis path only if needed and qualified, without adding raw audio transport.
- The spec's calibration margin of 6 dB conflicts with later noise checks requiring 10 dB speech/noise separation. Adopt one explicit coherent valid-calibration/noise rule in an ADR and boundary fixtures; initial constants are product assumptions pending real tests.
- A <200 ms cough should not count as phonation, but current 100 ms onset alone would allow some such bursts. Specify candidate onset versus minimum qualified activity and backdating; test duration boundaries rather than falsely claiming cough classification.
- Listener agreement is a subjective household check, not a clinical intelligibility score. Report blind/hidden-meter trials separately because a live arc can influence the listener. Do not suppress low agreement from the evaluation report; keep limitations prominent.

## Resolved privacy and pre-window contract

Use a bounded, ephemeral local PCM/level analysis ring while the phone's microphone is open. No MediaRecorder, audio blobs, stored audio, uploaded waveform, analytics or third-party recording scripts. Continuous local analysis does not authorize continuous outbound measurement.

1. Explicit precheck command carries session_id, unique window_id, duration_ms=2000 and requested aggregate shape. Phone badge says Measuring during that precheck.
2. Phone analyses those two seconds locally and sends one floor/quality aggregate (median, p20/p80, frame coverage, clipping, timestamps), then discards the ring. TV evaluates the documented noise gate.
3. Only after a valid precheck does TV send start_window for calibration/ahh/phrase. Phone emits bounded 20 Hz level frames only for that active, valid session/window. No level frames leave the phone between windows.
4. Stop/cancel/end_session is idempotent. End session calls track.stop for all capture tracks, disconnects/closes analysis resources, releases Wake Lock and sends acknowledged Mic off. Link loss/visibility interruption invalidates the current window; recovering cannot score stale buffered data.
5. Role-bound authenticated connection identity controls direction; schemas are validated, never executed as instructions. Relay must inspect shape to validate but must not persist/log content in the primary WebSocket mode.
6. If HTTP polling is implemented, disclose bounded transient relay payload buffering accurately. Server-side expiry checks and explicit cleanup are required; DynamoDB TTL is not instant secure deletion. A polling payload can include typed phrases/control data, so “only connection records stored” is no longer true.

Recommended compact UI wording:

> Audio stays on this phone and is never saved or uploaded. Only levels, typed phrases, listener responses, and connection details are sent to the relay and TV.

Use “Mic open, not measuring” between capture windows, “Measuring” for prechecks/noise/calibration/ahh/phrases only when actual samples arrive, and “Mic off” only when stop is acknowledged. “No audio upload” is accurate; “no data leaves the household” and “end-to-end encrypted” are inaccurate for the proposed relay.

Prior targets: SD ≤1 dB, spread within ±2 dB. 6 dB/4.5 dB slope targets only meaningful if acoustic input steps were independently established. |
| Noise and attribution | Quiet, fan, television speech, cough/transient, second speaker, continuous sound, changed room floor, moved phone. Fixtures validate arithmetic, real trials validate behavior. |
| VAD timing | 5/10/20-second sustained examples, silence, 100/150/200 ms transients and gaps; actual phone/timestamp traces aligned to independent observer/reference.
