## 5. Open items and rechecks

1. **No SDK install has been done.** B-001 (Rosetta, owner action) blocks the SDK install; the exact SDK build (`0.24.9311` and `0.24.9914` both appear in official material) must be pinned from `vega --version` after installation.
2. **RN 0.83 maturity.** Official release notes call RN 0.83 for Vega "early access" while both official samples default to it. If T03 shows blocking regressions, the documented fallback is the RN 0.72 line: starter tag `v0.24-RN72` (`cfaabd90947a12eb9f1085f71a898ae588ce814a`) and `@amazon-devices/react-native-svg ~2.0.0` / async-storage `~2.0.0`. Decide only with measured evidence (ADR-0007 says recheck at T03).
3. **a11y turbo module build for RN 0.83.** Confirm with `vega project doctor` that `@amazon-devices/kepler-a11y-settings-interface-turbo` `1.0.0` (not the `-rn-83` prerelease) is accepted on the 0.83 runtime.
4. **`kepler-cli-platform` pin.** Starter `~0.22.0` resolves to 0.22.14 today while the multi-TV starter pins `0.22.13-rn-83`; the lockfile must freeze one value after the first successful build.
5. **WSS from the Vega runtime** and the manifest capabilities it needs are untested; do not claim a working relay connection from the TV until T03/T12 produce evidence.
6. **Doc contradictions recorded, not resolved:** install page "Node 18.x or later" vs starter `.nvmrc` 22.22.2 / `engines >=22`; sample READMEs "NodeJS v18-v20"; svg page Polyline supported (intro) vs unsupported (table); async-storage RN 0.72 version on SDK 0.24 (`~2.0.0` snippet vs `~2.1.0` table).
7. Recheck every row before the final submission; the Vega docs, npm dist-tags and the Lambda runtime table change.
