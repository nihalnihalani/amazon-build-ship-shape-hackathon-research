# TV session machine

Authoritative state machine of `@atr/session-core` (contract revision 2, `docs/adr/AMENDMENTS-REV2.md`, `docs/PROTOCOL.md` revision 4; matches `src/machine.ts`). Product basis: master prompt journey A to J, ADR-0001, 0004, 0005, 0008, 0009. Evidence class of everything below: automated tests of a pure state machine. It says nothing about microphone validity, Vega behaviour, or the deployed relay.

## Shape

- Input: `TvInput` (`remote`, `ui`, `timer`, `transport`, `wire`, `a11y`, `app`). The store owns no timers: the app ticks `{ kind: 'timer', now }` every 100 to 250 ms. All time comes from the event or `deps.clock`; all identifiers come from `@atr/protocol`'s `createIdFactory(deps.randomBytes)`.
- Output: `TvView` (projection in `src/view.ts`) plus effects (`send`, `bind`, `connect`, `close`, `persist`, `delete_all`) run by `src/store.ts`.
- `remote ok` runs `view.preferredAction` if it is enabled; `remote back` and `ui back` are the same input. A `ui` action that is not in `view.actions` (or is disabled) is ignored, which is what makes a repeated OK harmless.
- The wire boundary is `src/wire.ts`, a thin wrapper over `@atr/protocol` (`parseWireMessage`, `MessageFactory` with role `tv`, `MessageIdDedupe`). The `wire` input is the raw text frame only (PK-09): objects, binary and other values are refused and counted as unparseable. Inbound messages are accepted only when the shared validators pass (they enforce quantisation and the PK-02 invariants) and the sender is the phone or the relay.

## Stages

Screens outside the 16 stages (`onboarding`, `home`, `settings`, `about`, `diagnostics`, `confirm_dialog`, `join_confirm`) are projections: `onboarding` and `home` are `idle`; `join_confirm` is `pairing`; `settings`, `about`, `diagnostics` and `confirm_dialog` overlay the stage underneath and Back restores it (never while a hidden attempt is unrevealed: see A4-03).

| `idle` (`onboarding`) | first launch (no saved settings) | I understand | `continue` | none | n/a |

## Rules

### Pairing and trust

- **Number matching (A3-06).** On `join.requested` the TV builds three two-digit choices: the real `confirm_digits` and two distinct decoys (uniform draws by rejection sampling from `deps.randomBytes`, falling back to a non-cryptographic source), shuffled. The view carries `{ deviceLabel, choices }` only; the real digits are never in a view or in Diagnostics. Actions are `[pick_choice_1, pick_choice_2, pick_choice_3, reject_join]`, `reject_join` preferred (OK and Back reject). The correct pick sends `join.confirm accept`; a wrong pick or a reject sends `join.confirm reject`, burns the code (no code or QR is shown until the relay's fresh `pairing.code` arrives) and a wrong pick says "That number did not match. Pair again." `device_label` is shown as "Name the phone gave: …" and is untrusted text.
- **Phone page origin (contract revision 3, T16 N-03).** The QR payload (`pairing.qrPayload`, which is also the link the TV shows) is `${origin}/#code=<CODE>`, built in one place (`phoneJoinUrl`). `origin` is `deps.phonePageOrigin` when it is a valid https origin (the phone page is on another host than the relay, for example CloudFront in front of an execute-api relay), otherwise the relay URL's https origin (unchanged). Valid means exactly `https://host` or `https://host:port` (DNS name, IPv4 or bracketed IPv6; port 1 to 65535) with no user info, path (not even a trailing slash), query, fragment or whitespace; scheme and host are lower-cased. An invalid or non-string value is ignored and Diagnostics says `phone_page_origin: relay origin (phonePageOrigin option invalid, ignored)`; the invalid value is never echoed or shown. Valid shows the origin itself, unset shows `relay origin`. The socket URL is always derived from `relayUrl`, never from this option.
- **Supersede (A3-07).** A `peer.state` for the phone with a different generation than the last one means the phone connection was replaced or restored: an open window is cancelled and unscored (`phone reconnected`), the microphone state becomes unknown, and "Phone reconnected." is shown. The first join is silent.
- **Credential rotation (A3-07).** `auth.ok.next_credential` replaces the credential, in memory only, and is what the next `auth.resume` presents. Never projected, stored or sent in any other message. A relay `revoked` error means a consumed credential was presented: "Pairing may be compromised. Pair again.", the room is dropped, any open window is cancelled, the session (if any) loses its floor and band, and the TV goes to pairing with a fresh room. Other ending errors do the same with the generic "pairing was lost" text (see the next item for which ones end the pairing). The store calls `transport.close(reason)` so the adapter stops retrying.
- **Relay errors, and a phone that is only offline (DEF-005).** `error { code: not_found, detail: peer_offline }` means the phone is temporarily gone, not that the room is: the TV keeps the room, the credential and the session, sets `peerConnected` false, shows the mic view `unknown` (never `off`), cancels any open window as unscored (`link_lost`) and never re-pairs. A must-deliver command the relay could not deliver (`window.cancel`, `session.end`, `window.stop`, `attempt.reveal`; the store tracks the `message_id` of each send and the error's `ref_message_id` names the dropped one) goes back into the queue and is flushed when `peer.state` connected returns, once; commands sent while the phone is known to be offline are queued from the start. After `peer.state` connected the mic view stays `unknown` until the phone's own `mic.state` arrives (which re-enables retry and the begin actions). Only these send the TV to pairing: `revoked` (compromised copy unless detail is `room_closed`), `expired`, `superseded`, `unauthorized` on the TV's own resume (an error before `auth.ok`) or with detail `resume_failed`, and `not_found` on the TV's own resume (room unknown). `not_found` with detail `no_such_join` only clears the stale join request ("The join request expired."). Everything else (`unauthorized` or `not_found` on an authed link, `unauthenticated`, `rate_limited`, `payload_too_large`, `internal`, ...) is a banner ("The relay reported: <code>.") and leaves the stage alone; `relay_errors` and `peer_offline_errors` are counted in Diagnostics.
- **session.begin acknowledgement (DEF-003).** The phone ignores everything but the join protocol until its owner confirms (A3-01), so it may drop `session.begin`. The TV sends no `precheck.start` or `window.start` (and offers no begin or retry action) until the phone has acked a `session.begin` of this session as `applied`; the ack names the `message_id` the store gave the message. Until then `permission_pending` stays up with "Waiting for the phone." even if the microphone is open, and a later ready screen disables its begin action. Defence in depth: while a session is active and its begin was sent, a phone `mic.state` whose `session_id` is null or another session, or an ack with detail `unknown_session`, makes the TV send `session.begin` again (same session id and payload) and then the current `session.state`, at most once per 2 s (the first send starts the clock; resends are counted in Diagnostics). Nothing is resent with no session, an ended session, no phone or no link. The ack, once given, is not taken back by a later resend or reconnect.
- **Identifiers.** `window_id` is unique per measurement (protocol revision 4): the quiet-check precheck, each pre-window precheck and each capture has its own fresh `window_id`; the pre-window precheck and its capture share the attempt's `attempt_id`; a retry gets new ids. `window.cancel` names the measurement that is open. Stale filtering is per `window_id`: anything addressed to a closed, cancelled or different window is ignored and acked `ignored_stale`.
- **Heartbeat.** While the socket is open and the TV has sent nothing for 10 s, a `ping` goes out on the next timer tick. `pong` only increments a counter.
- **Must-deliver commands (QA-03).** `window.cancel` and `session.end` (and `unpair`/`room.close`) sent while the link or the phone is down are queued (bounded, deduplicated) and flushed after `auth.ok` or when the phone returns. A pairing the relay ended drops them.

### Measurement (verdict math is TV-owned, `verdict.ts`)

- **Capture starts at the phone's first level frame (DEF-007).** Over a real link the phone starts measuring some time after the TV sent `window.start`, so the TV does not prompt the speaker at send time. A calibration, vowel or phrase window has phases `lead` (quiet lead) then `precheck` (phrase and vowel only), then `starting` (from the moment `window.start` is sent), then `capture` and `closing`. In `starting` the view says "Starting the phone's measurement…" (the vowel title stays "Sustained sound (optional)"), has no timer, no meter, no prompt to speak (no "say ahh" or "say the phrase now"), no actions and no announcement, and OK and `stop_early` do nothing. The first valid `level` frame for that window (right ids, quantised, passes the PK-02 checks, not a duplicate, also for a hidden window where frames are validated but never shown) moves the window to `capture`: the prompt, the elapsed timer, the meter (visible windows only) and `stop_early` appear and the timer and the window maximum (`max_duration_ms`, stop at maximum + 500 ms) count from that frame, not from `window.start`. Frames of another window, off-grid or failing frames and duplicates do not start the capture. If no valid frame arrives within `RESULT_GRACE_MS` (3 s) of `window.start`, the TV sends `window.cancel` (reason `timeout`), records `no_start` and shows "The phone did not start measuring. Try again." with retry. A try that never started (no frame, Back or link loss while `starting`) does not count as started: it is not a phrase attempted in the summary and does not use up a blind check, so the retry at a blind position is still blind. A `window.result` that arrives with no frame before it is still accepted (frames can be lost on the way). A late frame or result for a window the TV cancelled is stale. The precheck is not changed. A phone that needs the TV's prompt to start (a fake phone in a test) must send its first `level` frame promptly after `window.start`.
- **Quiet lead.** After OK on a begin action the first command is sent after 1500 ms, or 3000 ms when the screen reader is on (A8-02). Both are configurable in settings (`quietLeadMs`, `quietLeadScreenReaderMs`, 500 to 10 000 ms; anything else is ignored) and shown in Diagnostics. A window that is already in its lead keeps its own. During the lead, precheck and capture the view is `capturing`, announcements are null, and (before capture) no control is focusable so a repeated OK cannot press Cancel. Back cancels at every phase.
- **Screen reader script (A8-02).** With `{ kind: 'a11y', screenReader: true }` each ready screen carries a fixed script and its announcement includes it: phrase "After this message, wait three seconds, then speak. Measurement lasts eight seconds."; calibration "… six seconds."; vowel "… up to thirty seconds."; quiet check "After this message, stay quiet for the whole check. Measurement lasts five seconds." The number of seconds to wait follows the configured lead.
- **Re-validation (A1-05..09).** The TV recomputes validity from the numbers; a phone claim that disagrees is the TV-local reason `integrity` and the attempt is unscored. Priority: interrupted, nonfinite (more than 5 % of frames), low_coverage, silent_input (floor below -110 dBFS: "The phone microphone looks muted or blocked."), clipped, unstable_floor, burst_noise, too_loud. The pre-window precheck uses only interrupted, nonfinite, low_coverage, silent_input, clipped and burst_noise. Integrity also checks the PK-02 cross-field invariants (percentile order, counts, durations; the shared validators already enforce them on the wire) and the TV-only timing rule `duration_ms <= max_duration_ms + 500`.
- **Floor guard.** `window.start.vad_floor_dbfs` must be -110 to -30: a floor outside that range (or none) refuses to start the window and shows the silent-input copy.
- **Calibration:** accepted when valid, `active_ms >= 400` and margin (`p95_active - session floor`) at least 13 dB. Skip calibration is offered only when this session already has a band; otherwise "Continue without a band" runs the phrases unscored ("No band set: results not scored") with the listener check. A failed retry keeps an earlier band. A phrase or vowel window is valid with any accepted segment (A1-04).
- **Gate** (before each phrase window and, when a band exists, before the vowel): block when rise at least 6 dB, or margin minus rise below 10 dB, or the precheck is invalid. A blocked attempt is recorded unscored (`room_noisier` or the precheck reason), never started, and does not count as the blind attempt. Diagnostics shows the calibration margin and the tolerated rise (A1-08).
- **Verdict:** reached when `p95_active - floor >= margin - 1`; borderline when within 1 dB of that edge. Wording "Reached today's relative level band" or "Below today's relative level band".
- **Qualification (A9-02).** `settings.qualification` is `not_run` (initial), `passed` or `failed`. Unless `passed`, band result labels end with " (unqualified phone)". `failed` (or a configured `listener_edition`) forces Listener Edition: the listener check is always on, no band verdict is computed or shown, the band tick is absent, the result label is the listener's answer, and the summary says so and lists the listener answers. Settings shows the state.

### Blind check, listener and reveal

- **Hidden:** positions 3, 6, 9 when present, first captured attempt only. Meter and result are absent from the view (not flagged); no string depends on level, verdict or validity; level frames are validated but not stored; `capturing` implies `announcement === null`. A retry is visible and identified by `attemptNumber > 1` and `hidden === false`.
- **A4-01.** For a hidden first attempt every window that closes by stop, completion, timeout or a phone-reported invalid result (any reason except `interrupted`) enters `response_pending` with the same neutral prompt ("How did that feel?") and, in family mode, the same `listener.open`. "Not scored" and its reason appear only at reveal. Speaker Cancel, link loss, interruption and a precheck timeout keep the immediate path. A listener response the TV did not solicit gets `ack ignored_stale` with an empty detail.
- **A4-03.** Between capture close and reveal of a hidden attempt: `meter` is null, Settings, History, Diagnostics and About are not offered (and are not projected even if an overlay were open), Diagnostics redact the step, and the leave dialog still works.
- **A4-04/05.** Keep waiting sends a fresh `listener.open`. Continue without a listener response records `missing` and sends `attempt.reveal` at once (the phone locks its controls); `attempt.reveal` is sent once per attempt. The first on-time response wins; later on-time responses are `ack rejected` (`already_answered`). A response after reveal, or after "continue without", is stored late and acked `applied` (`late`); a second one is `already_answered`. Late responses are never in the agreement denominator.
- **A4-06.** Borderline attempts are eligible for agreement and also counted separately.
- **QA-05 (phone-visible stage).** `session.state` never carries `response_pending` or `reveal`: the phone sees `phrase_active` from the capture start until the next `phrase_ready` (or `session.end`); `listener.open` is the explicit signal.
- **Cues:** at most 3 per session (4th: ack `rejected`, no chip); rejected while a window is open; chip for 3 s; `session.state` carries `cues_used`.
- **Phrases:** validated by the shared validators and again by `validatePhraseBank`. A `phrases.update` replaces the bank for the current session until the first phrase window begins or the first phrase is skipped (QA-04), otherwise for the next session (`applied`, `next_session`). `session.begin.phrase_count` reflects the bank when it was sent. A resumed session uses the saved bank and clamps the position to it.

### Announcements (A8-01, QA-12)

While a precheck or capture is open, nothing is announced; banners and cue chips are visual only and their text is queued. For a hidden attempt the queue is held until the reveal. The screen's own text is never replaced: queued text (a held banner, or a cue, which is queued the moment it arrives) is appended after it, each item once, and stays in the announcement until the stage changes, so the live-region text does not change when the 3 s chip expires. A screen change inside the chip announces the new screen alone; the cue had its turn on the earlier one.

### Storage and deletion

- **Storage** (`atr:v1:*`): meta, settings, phrases, per-session records, index, active checkpoint. Retention is 8 days (A5-04). Session records, the index and the checkpoint hold positions and counts only: never phrase text, cue text or device labels; the phrase bank persists until deleted (About says so). The checkpoint (written at capture start and after each reveal or phrase change) contains nothing about an unrevealed attempt: no verdict, reason, window numbers, rating or listener answer (A4-02), no credentials, no pairing code. A checkpoint older than 12 h is discarded on launch (A5-03). A checkpoint for a session that already has a final record, or a record written after the checkpoint, is dropped, and Discard never overwrites a final record (QA-02).
- **Write order (QA-02, QA-07).** The finished record is written, then the index, then the checkpoint is cleared, and the checkpoint is never cleared if the record write failed (an error is shown and the session is recoverable on the next launch).
- **Dates (QA-10, QA-11).** A stored `localDate` must be a real calendar date (2026-13-45 is corrupt). A record is pruned on launch when it is older than 8 days or its `endedAt` or `startedAt` is more than one day ahead of the clock (a clock that was wrong and then corrected); a checkpoint saved more than a day ahead is discarded like a stale one. Home and history never show a day after today. A clock that returns something that is not a date falls back to the UTC date of the same instant and is counted in Diagnostics (`clock_date_invalid`). Counts in copy use the right number ("1 phrase was attempted", "1 phrase completed").
- **Validation (A5-05).** Values read from storage are validated like wire data (ranges, enums, identifier and date shapes). An invalid value is treated as absent and counted; Home and Settings offer deletion. A failed removal of expired summaries is surfaced and keeps them. Unknown future versions are never overwritten (persistence is disabled and Settings offers delete). Pure v0 to v1 migration.
- **Delete (A5-01).** Confirmation (Cancel preferred) then: best-effort `unpair` and `room.close` (banner "Relay cleanup in progress.", then "confirmed" when the relay closes the connection or "not confirmed" after 5 s or when no live link), credentials and room identity dropped (no reconnect creates a room), all `atr:` keys removed and verified through `getAllKeys`, memory reset. Success is never claimed when verification finds keys: an error and a retry are shown instead.
- **Fixture mode** swaps in an in-memory store and labels every screen "Fixture replay".
- **PK-12.** An NFC self-test at construction (`e` + U+0301 must become U+00E9) is shown in Diagnostics, with a banner if it fails.

### Link, session end and summary

- **Link loss** (`reconnecting`, `offline`, `failed`, peer gone, relay `peer_offline`): mic view `unknown` until the phone reports again (never `off`), any open window is cancelled and unscored, a fresh explicit begin is required. The room and the session are kept (see DEF-005 above).
- **Back from a session** asks to confirm leaving (Cancel preferred) once practice has begun. Dialogs for delete, reset and unpair always prefer Cancel; closing a dialog returns focus to the control that opened it.
- **Summary and history:** counts, hidden/visible agreement with denominators, late responses and borderline count are structured fields; `lines` holds notes only (no counts). A day with any incomplete session is flagged incomplete; there is no comparison or trend between days.
